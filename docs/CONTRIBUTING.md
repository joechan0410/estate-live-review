# 贡献说明

欢迎改进数据适配、分析规则、报告体验和测试。提交前先说明具体问题、触发条件及预期结果。

## 本地验证

在仓库根目录运行 Python 测试：

```sh
python -m unittest discover -s tests -v
python -m unittest discover -s plugin/skills/douyin-live-replay-audio/scripts -p 'test_*.py' -v
python -m unittest discover -s plugin/skills/estate-live-workbench/scripts -p 'test_*.py' -v
```

前端使用 Node.js 22.12 或更高版本；CI 使用 Node.js 22：

```sh
cd web
npm ci
npm test
npm run build
```

GitHub Actions 会执行 Python 主工具与两组插件测试、前端测试和生产构建。插件保留独立脚本副本，修改共享行为时应同步对应入口及测试。音频模型或外部服务集成的变更，请在 PR 中说明使用的环境、样本范围与实际验证结果。

## 提交内容

- 每个 PR 聚焦一个清晰的功能或修复，写明用户可见的行为变化。
- 为去重、时间边界、评分分母、缺失值和数据映射等逻辑补充合成测试。
- 修改评分规则时，附上旧结果、新结果及变化原因，说明配置兼容方式。
- 页面变更提供相关视图截图，并检查筛选、证据详情和小屏布局。
- 更新依赖时同步锁文件；新增第三方代码或素材时附来源与许可证，保留上游声明。

## 示例数据

测试资料应可独立复现，使用虚构项目、主播和客户标识。提交前检查新增文件：凭据、真实客户信息、私有链接、录音、转写和生产导出文件均保留在自己的环境中。

涉及自动识别的改动，请区分候选结果、人工核对结果和未覆盖范围。缺项保持为空，使用明确的证据解释分母与数值变化。

## PR 描述

建议用以下顺序说明：

1. 解决了什么问题，如何触发。
2. 变更后的行为，以及相关配置或数据格式变化。
3. 实际运行的测试与必要截图。
4. 尚未验证的具体集成环境（如有）。
