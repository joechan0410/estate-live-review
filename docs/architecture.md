# 系统结构

Estate Live Review 将直播资料整理、转写处理、证据复核、评分和报告展示分开。页面自带合成示例，可以先体验报告，再接入自己的数据。

```text
授权取得的媒体、字幕、评论和留资数据
                  │
                  ▼
pipeline/：资料收集 → 转写整理 → 音频分析 → 证据与评分
                  │
                  ▼
审核后的数据与报告快照
                  │
                  ▼
web/：React 报告页面、筛选、证据查看与导出
```

| 目录 | 职责 |
| --- | --- |
| `pipeline/` | 独立 Python 命令行工具及评分配置 |
| `tests/` | Python 单元测试与合成输入 |
| `web/` | React + Vite 报告界面及合成演示数据 |
| `plugin/` | 可选的工作台技能与已有工作区集成工具 |
| `docs/` | 使用、结构与贡献说明 |
| `.github/workflows/` | 自动测试及前端构建 |

## 运行入口

**报告演示**直接从前端合成数据生成快照，按 `queries[id].rows` 组织页面查询结果。演示支持周度、累计、月度视角，以及项目、主播、七维评分、内容价值、问答、留资、录音和证据详情。切换示例周使用 URL 的 `week` 参数。

**数据处理**通过 `python -m pipeline.<模块>` 运行。基础评分测试使用 Python 标准库；媒体采集和音频模型具有各自的依赖。各模块的输入输出由参数及文件约定连接，接入新平台时可以替换采集层。

评论到留资的归属模块 `pipeline.attribute_comment_leads` 使用直播间、完整客户标识、末次前序评论和已核实际主播时段。它单独输出闭合归属、待核记录、重复记录及统计分母，供评分与报告适配使用。

前端当前的合成数据适配位于 `web/src/demo-data.js`。接入自己的报告数据时，保持现有查询结构，逐项映射经过审核的字段。Python 命令输出与页面快照之间的字段映射需要按具体数据源完成。

**工作台插件**可以识别当前开源仓库中的 `web/` 和 `pipeline/`，也可以连接已有分析工作区。独立仓库模式通过 npm 构建前端，不依赖 Data 插件；原工作区模式沿用对应工作区的构建入口。插件中的脚本副本支持独立分发，CI 同时运行它们的合成测试。

## 证据与数值

- 保留原始文件、录制标识、时间范围和引用来源，便于从报告回查。
- 自动提取的口播、问答和行动提示作为复核候选；人工结论记录实际查看的范围。
- 主播身份、实际交接与排班分别保存。姓名或时段待核时，保留未知状态。
- 缺失数值保留为空；分母和范围变化需要同步更新评分与展示。
- 新增数据适配器时，使用可追溯的原始标识关联记录，并为去重、跨段和缺项行为增加测试。

运行方式见 [使用说明](usage.md)，提交变更见 [贡献说明](CONTRIBUTING.md)。
